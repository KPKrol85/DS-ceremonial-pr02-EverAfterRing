# Changelog

All significant changes to this project are documented in this file.

Development history from before the migration to this repository was kept in the previous
portfolio repository and is not reconstructed here.

## [Unreleased]

### Added

- Added the EverAfter Ring static multi-page site as an independent repository, including the HTML pages, the shared header and footer in `partials/`, the CSS and JavaScript sources, project assets, and the Node-based production build pipeline in `scripts/build.mjs` and `scripts/optimize-images.mjs`.
- Added a custom `404.html` error page, so an unknown address lands on a page carrying the site's own design, shared shell, and navigation instead of the hosting platform's default. It is registered as an eleventh entry in the page list that `vite.config.js` uses as its multi-page input, so the production build resolves the shared header and footer into it and inlines the theme bootstrap exactly as it does for the other pages. Because the hosting platform serves this one document for any missing address, including nested ones, the page declares `<base href="/">` so its links and assets resolve against the site root from any depth, and it re-points the skip link at the address actually being served so that link stays a same-document jump. The page is kept out of search results and out of discovery: it carries `noindex, follow`, has no canonical address of its own, and is not listed in `sitemap.xml`. It owns no primary-navigation link, so the build's single active-navigation-state contract is unaffected.
- Added the invalid state of the contact form's validated fields to the accessibility tree. A field that fails validation now carries `aria-invalid="true"`, so a screen reader announces it as invalid when the visitor reaches it instead of relying on the error message alone, and the state disappears again as soon as the field becomes valid — on the next blur, on the next submit, or while typing, which is when the message was already being cleared. The state is written and removed by the same two functions that write and clear the message, so it cannot drift out of step with the field's validity across repeated correction cycles. Nothing else about the form changed: the validation rules, the required fields, the Polish messages, the error-message associations, the status region, the focus moved to the first invalid field, and the Netlify Forms submission contract are all as before, and the new state carries no styling of its own. The behaviour is covered by a new focused Chromium test in `tests/`, which submits the form with the required fields empty and checks the first invalid field's state, focus, and message, then checks that entering a valid value clears them.

### Removed

- Removed eight unused files from the asset tree: the six standalone theme and social icons in `assets/svg/`, the raster `assets/logo/logo.png`, and `assets/placeholders/placeholder.jpg`. None was referenced by any page, stylesheet, script, or the web app manifest, and each duplicated something the project already provides — the icons are maintained inline in the shared header and footer, which is the copy the site renders, the logo ships as `assets/logo/logo.svg`, and the social share image as `assets/og-img/og-img.jpg`. Every deployment is roughly half a megabyte smaller as a result.

### Fixed

- Fixed the privacy policy, cookie policy, and terms pages to describe the functionality the site actually implements, including contact form submission through Netlify Forms, the two browser-local `localStorage` entries used for the theme choice and the project notice, and the embedded Google Maps frame on the contact page, while keeping the demonstration-project framing.
- Fixed the theme runtime so it keeps the theme resolved before the first paint. With no saved choice, a visitor whose system prefers dark now stays on the dark theme after the page loads instead of reverting to light, and the theme toggle reports the theme actually in effect.
- Fixed the mobile navigation so the panel is closed by default in the markup and the stylesheet. It no longer covers the page when JavaScript is unavailable or has not run yet, and scripting is required only to open it.
- Fixed the dropdown indicator on the contact form so it follows the active theme. The chevron on both required select fields is now clearly visible in the light theme, where it was previously almost indistinguishable from the field background.
- Fixed the project notice modal so it behaves as the modal dialog it declares itself to be: keyboard focus stays inside it while it is open, `Escape` closes it, clicking the backdrop dismisses it, and focus returns to where it was before the notice appeared.
- Fixed the technology table on the cookie policy page so it scrolls horizontally within its own region on narrow screens, with a visible keyboard focus state, instead of overflowing the page.
- Fixed the project notice so it still appears and can be dismissed in a browser that blocks site data. A failed read or write of the stored acceptance no longer surfaces as an uncaught error.
- Fixed the structured data on all ten pages so it no longer presents the demonstration site as an operating local business. The `LocalBusiness` block with real contact details was replaced by linked `WebPage` and `WebSite` data stating the project's demonstration character, matching the framing already used in the interface and the legal pages, and `README.md` describes the new contract.

### Documentation

- Added the project license as a bilingual Polish and English proprietary KP_Code license bound to this project and repository, with the Polish version stated as authoritative in case of divergence.

### Build and Tooling

- Added repository ignore rules for dependencies, the generated `dist/` output, test and coverage output, tool caches, environment files, logs, and editor or operating system artifacts, while keeping `assets/`, `package-lock.json`, and the Codex environment configuration tracked.
- Added a Codex environment configuration that installs dependencies with `npm ci` during worktree setup.
- Added a repository line-ending policy in `.gitattributes` that stores tracked text files with LF and keeps binary image and font formats out of line-ending conversion, so a one-line source edit produces a one-line diff regardless of the contributor's platform.
- Changed `npm run build` to produce the deployment output in `dist/` without generating images, so the documented build no longer rewrites version-controlled files under `assets/img/`. Image variants are now produced only by running `npm run optimize:images` explicitly, and the build documentation in `README.md` describes the new sequence.
- Changed the production build from the custom Node pipeline in `scripts/build.mjs` to Vite, while keeping the HTML, CSS, and Vanilla JavaScript multi-page architecture, the ten top-level pages, and `dist/` as the deployment output. `vite.config.js` declares the ten pages as multi-page entries and owns the contracts the build tool does not: `scripts/html-shell.mjs` resolves `partials/header.html` and `partials/footer.html` into every production page, and it still fails the build when a partial host is missing from a source file or when a page belonging to the primary navigation does not end up with exactly one `nav__link` carrying `aria-current="page"`. Vite is build and development tooling only — no runtime framework and no runtime dependency was introduced, and the pages the browser loads remain plain HTML, CSS, and ES modules. `scripts/build.mjs` was removed together with the pipeline it implemented.
- Changed how the theme bootstrap is delivered in production while keeping the behaviour it guarantees: `js/theme-bootstrap.js` stays outside the JavaScript bundle, and the build now minifies it and inlines it in place of its own script tag instead of emitting it as a separate minified file. The theme is still resolved synchronously, ahead of the stylesheet and before the first paint, and it no longer costs a separate request. The build also fails when that script tag is missing from a source page, which the previous pipeline did not check.
- Changed the deployment payload handling so it survives the new bundler: `assets/img-src/` remains excluded from `dist/`, and `assets/` — kept at its authored paths, because the web manifest, the absolute metadata URLs, and the generated `srcset` values all reference it there — together with `robots.txt` and `sitemap.xml`, is still copied into the build output. Bundled CSS and JavaScript are emitted into `dist/css/` and `dist/js/` with content hashes instead of the previously hand-named `.min` files.
- Changed the local workflow to the Vite scripts: `npm run dev` serves the sources on port 8181, `npm run build` writes `dist/`, and `npm run preview` serves the built directory on port 8182. `start-local-preview.bat` now starts `npm run dev` instead of a Python HTTP server, and the `clean`, `build:css`, `build:js`, `build:html`, and `build:assets` scripts were removed because the build empties `dist/` and performs those stages itself. `README.md` describes the new tooling, scripts, ports, and build sequence in both language sections.
- Removed the direct `esbuild` and `lightningcss` dependencies once Vite took over JavaScript and CSS bundling and minification, leaving `vite` and `sharp` as the project's only direct dependencies. `sharp` is retained as the explicit image-generation dependency behind `npm run optimize:images`, which is unchanged and remains separate from the build.
- Added an automated browser smoke-test baseline in `tests/`, run by `npm run test:smoke`. The command builds `dist/` and then runs nine Chromium tests against the Vite production preview, so the suite exercises the same resolved shared shell and inlined theme bootstrap the deployment ships rather than the development server. The coverage is deliberately a baseline: three representative pages — the home page, a secondary public page, and the contact page — are checked for their title, level-one heading, resolved header and footer, applied theme, and absence of page errors; one test follows the shared primary navigation to a second document and confirms the active navigation state the build resolves into it; two cover the theme, both a stored dark preference applied before the first paint and the toggle switching the theme and persisting the choice across a reload; one opens and closes the mobile navigation panel at a 390 px viewport, asserting its state and focus handling; and two cover the project notice, on a first visit and with a stored acceptance. The preview host and port are pinned so the base URL matches on every platform, and the suite never attaches to a preview server left running from an older build. `@playwright/test` was added as a development dependency; no runtime dependency, page, or deployed output changed.
